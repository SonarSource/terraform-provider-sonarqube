# sonarqube_cloud_project_permissions (Resource)

This resource manages the complete set of permissions for one group or user on one project. Destroy removes the selected principal's grants on the project. It does not change other principals.

The allowed permissions are `admin`, `codeviewer`, `issueadmin`, `securityhotspotadmin`, `architectureadmin`, `scan`, and `user`. The `Anyone` group is not supported.

## Grants from the permission template

When SonarQube Cloud creates a project, it applies the default permission template, so the project already has grants. If the principal already has grants on the project, create takes control of them. It removes the grants that are not in `permissions`.

## Public projects

All users can browse a public project and see its source code. SonarQube Cloud does not store a grant of `user` (Browse) or `codeviewer` (See Source Code) on a public project. If `permissions` has one of these values and the project is public, the apply fails and sends no change. Remove these values, or make the project private.

A change of the project visibility also changes the grants. When a project becomes public, SonarQube Cloud removes `user` and `codeviewer`. When a project becomes private, SonarQube Cloud gives `user` and `codeviewer` to each group that has a different permission on the project. The next plan then shows a change.

## Administrators

SonarQube Cloud does not protect the last project administrator. An apply can remove `admin` from all principals of the project.

## Example Usage

```terraform
resource "sonarqube_cloud_project_permissions" "developers" {
  organization = "my-org"
  project_key  = "my-project"
  group_name   = "Developers"
  permissions  = ["user", "codeviewer", "issueadmin"]
}
```
