# sonarqube_cloud_organization_binding (Resource)

Binds a SonarQube Cloud organization to an organization on a DevOps platform. Only github.com is supported.

~> **The API cannot remove a binding.** `terraform destroy` drops this resource from the state and gives a warning, but the binding stays. The server removes a binding only when it deletes the organization, because that also removes the records that this API writes.

To destroy an organization and its binding together is therefore correct. Terraform deletes the binding before the organization that it depends on.

## Example Usage

```terraform
resource "sonarqube_cloud_organization" "example" {
  key  = "my-organization"
  name = "My organization"
}

# Which GitHub application does this instance own? A binding accepts an
# installation of that application only.
data "sonarqube_cloud_dop_applications" "github" {
  dev_ops_platform = "github"
}

output "install_the_application_from" {
  value = [
    for application in data.sonarqube_cloud_dop_applications.github.applications :
    "https://github.com/apps/${application.application_key}"
  ]
}

# Install the application on the GitHub organization, then read the
# installation identifier from the address that GitHub shows afterwards:
# https://github.com/organizations/<github-org>/settings/installations/<installation_id>
resource "sonarqube_cloud_organization_binding" "example" {
  organization_key = sonarqube_cloud_organization.example.key
  installation_id  = "12345678"
}

# A destroy removes the organization and the binding together. The API cannot
# remove a binding on its own: the server drops it when it deletes the
# organization.
```

## Schema

### Required

- `installation_id` (String) Identifier of the GitHub application installation. It is the last segment of the address of the installed application on GitHub.

The installation must belong to the GitHub application of this SonarQube Cloud instance. Read the `sonarqube_cloud_dop_applications` data source to find that application.

~> This cannot change after the binding exists. The API allows a change for a binding to GitHub Enterprise only. To replace the resource does not help, because a binding cannot be deleted.
- `organization_key` (String) Key of the SonarQube Cloud organization to bind. The provider reads the organization to find the internal identifier that the bindings API needs.

### Optional

- `dev_ops_platform` (String) DevOps platform to bind to. Only `github` is supported, and that is the default.
- `repo_auto_import_enabled` (Boolean) Whether repositories are imported automatically.

~> The server accepts this for GitHub only, and only while the matching feature is on for the organization. It writes `false` otherwise, and the provider then reports which value the server holds.

### Read-Only

- `binding_type` (String) Type of the binding, as the API reports it.
- `dev_ops_platform_url` (String) Address of the organization on the DevOps platform, as the server reports it. The bind call takes no address, so this is read only.
- `dop_flavor` (String) Variant of the binding, such as `GITHUB_GHEC_DR`. Holds no value for a binding to github.com. This provider cannot make a binding to GitHub Enterprise, but it reports the variant of one that was made elsewhere.
- `id` (String) Identifier of the binding.
- `organization_id` (String) Internal identifier of the bound organization.
- `organization_uuid_v4` (String) Identifier of the bound organization in the form of a UUID.
