# sonarqube_cloud_enterprise (Resource)

This resource creates a SonarQube Cloud enterprise with a license and its
first organization. The provider must use a user token. Scoped organization
tokens are not supported.

`key`, `license` and `organization` cannot change after create. A change to
one of them stops the plan. The provider never replaces the enterprise. A
change to `name` or `avatar` updates the enterprise in place.

## Destroy

~> Destroy deletes the enterprise and its portfolios.

- The license cannot be used again. A new enterprise needs a new license.
- The organizations stay, on a paid plan without enterprise features.

We recommend `prevent_destroy`:

```terraform
resource "sonarqube_cloud_enterprise" "main" {
  # ...

  lifecycle {
    prevent_destroy = true
  }
}
```

## Example Usage

```terraform
variable "enterprise_license" {
  type      = string
  sensitive = true
}

resource "sonarqube_cloud_enterprise" "main" {
  key          = "my-enterprise"
  name         = "My enterprise"
  license      = var.enterprise_license
  organization = "my-organization"

  lifecycle {
    prevent_destroy = true
  }
}
```

## Schema

### Required

- `key` (String) Enterprise key. It cannot change after create.
- `license` (String, Sensitive) Enterprise license key. A license can be used for one enterprise only. It cannot change after create. The API does not return it, so it is null after import.
- `name` (String) Enterprise name.
- `organization` (String) Key of the first organization of the enterprise. It cannot change after create. The API does not return it, so it is null after import.

### Optional

- `avatar` (String) Address of the avatar image. The default is no avatar.

### Read-Only

- `id` (String) Enterprise UUID.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# Import with the enterprise key. The API does not return `license` and
# `organization`, so they are null after import. The next apply writes the
# values of the configuration to the state, and does not change the enterprise.
terraform import sonarqube_cloud_enterprise.main my-enterprise
```
