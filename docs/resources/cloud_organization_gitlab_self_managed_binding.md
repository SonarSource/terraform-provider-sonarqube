# sonarqube_cloud_organization_gitlab_self_managed_binding (Resource)

Binds a SonarQube Cloud organization to a top-level group on a GitLab Self-Managed instance. It also stores the GitLab configuration of the organization, which holds the addresses of the instance.

The organization must have the Enterprise plan. SonarQube Cloud must reach the GitLab API over HTTPS at a public address, with a certificate of a public certificate authority.

~> **The API cannot remove a binding.** `terraform destroy` drops this resource from the state and gives a warning, but the binding and the GitLab configuration stay. The provider keeps the configuration, because a binding without it cannot reach GitLab. The server removes the binding when it deletes the organization, and the configuration then belongs to no organization that exists.

To destroy an organization and its binding together is therefore correct. Terraform deletes the binding before the organization that it depends on.

## Example Usage

```terraform
variable "gitlab_token" {
  description = "GitLab personal access token with the api scope, of an account that owns the group."
  type        = string
  sensitive   = true
}

resource "sonarqube_cloud_organization" "example" {
  key  = "my-organization"
  name = "My organization"
}

# A binding to GitLab Self-Managed needs the Enterprise plan, so the
# organization must belong to an enterprise.
data "sonarqube_cloud_enterprise" "example" {
  key = "my-enterprise"
}

resource "sonarqube_cloud_enterprise_organization" "example" {
  enterprise_id = data.sonarqube_cloud_enterprise.example.id
  organization  = sonarqube_cloud_organization.example.key
}

resource "sonarqube_cloud_organization_gitlab_self_managed_binding" "example" {
  organization_key = sonarqube_cloud_enterprise_organization.example.organization
  server_url       = "https://gitlab.example.com"
  group            = "my-group"
  access_token     = var.gitlab_token
}

# A destroy removes the organization and the binding together. The API cannot
# remove a binding on its own: the server drops it when it deletes the
# organization.
```

## Schema

### Required

- `access_token` (String, Sensitive) GitLab personal access token with the `api` scope. SonarQube Cloud uses it to read the group and to report analysis results. Use a token of a technical account that owns the group.

The API never returns the token, so the provider cannot see a change made outside Terraform. A new value here replaces the token of the binding.
- `group` (String) Path of the top-level GitLab group, for example `my-group` for `https://gitlab.example.com/groups/my-group`. The owner of `access_token` must own this group.

~> This cannot change after the binding exists. To replace the resource does not help, because a binding cannot be deleted.
- `organization_key` (String) Key of the SonarQube Cloud organization to bind.
- `server_url` (String) Address that opens the GitLab instance in a browser, for example `https://gitlab.example.com`. Include the installation path if the instance uses one. Do not include a group or a project path.

### Optional

- `api_url` (String) Address of the GitLab REST API. The default is `server_url` followed by `/api/v4`. Set it only when the instance uses a different API address, for example behind a proxy.

### Read-Only

- `configuration_id` (String) Identifier of the GitLab configuration of the organization.
- `dev_ops_platform_url` (String) Address of the group, as the server reports it.
- `group_id` (String) Numeric identifier of the group on the GitLab instance.
- `id` (String) Identifier of the binding.
- `organization_id` (String) Internal identifier of the bound organization.
- `organization_uuid_v4` (String) Identifier of the bound organization in the form of a UUID.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# Import with the organization key. The API never returns the token, so the
# next apply writes the configured access_token to the binding.
terraform import sonarqube_cloud_organization_gitlab_self_managed_binding.example my-organization
```
