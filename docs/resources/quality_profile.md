# sonarqube_quality_profile (Resource)

This resource manages a custom quality profile of one language. A profile can extend one parent profile, for example a built-in profile such as `Sonar way core`. Then it gets the rules of the parent. A change to `name` or `parent_key` changes the profile in place. A change to `organization` or `language` replaces it.

## Built-in profiles

The built-in profiles are read-only, and the import refuses them. Use the `sonarqube_quality_profile` data source to get the key of a built-in profile, for example to use it as `parent_key`.

## Delete

A delete also deletes all the profiles that extend the profile. Terraform does not know about this. When a profile of the configuration extends a deleted profile, the next plan creates that profile again. When the configuration sets `parent_key` to the `key` of a different resource, Terraform destroys the child profile first.

A replacement of the parent also deletes the child on the server, but the plan only changes the `parent_key` of the child, so the apply fails. Add `lifecycle { replace_triggered_by = [sonarqube_quality_profile.<parent>.key] }` to the child, so that Terraform replaces it together with the parent. Refer to `key`, not to the whole resource: a reference to the whole resource also replaces the child when the parent only gets a new name or parent.

SonarQube Cloud refuses to delete a profile when the profile or one of its descendants is the default profile of the language. Set a different default profile first.

## Combined quality profile groups

SonarQube Cloud refuses to change the parent of a profile or to delete it, when the profile is a member of a combined quality profile group. Manage such a profile through the group.

## Import

Import a profile with `<organization>/<language>/<name>`. The name can contain `/`.

## Example Usage

```terraform
data "sonarqube_quality_profile" "sonar_way_core" {
  organization = "my-organization"
  language     = "java"
  name         = "Sonar way core"
}

resource "sonarqube_quality_profile" "backend" {
  organization = "my-organization"
  language     = "java"
  name         = "Backend"
  parent_key   = data.sonarqube_quality_profile.sonar_way_core.key
}

# A replacement of the parent also deletes the child on the server. The
# lifecycle block makes Terraform replace the child together with the parent.
# It refers to key, which changes only when the parent is replaced, so a
# rename of the parent does not replace the child.
resource "sonarqube_quality_profile" "backend_payments" {
  organization = "my-organization"
  language     = "java"
  name         = "Backend payments"
  parent_key   = sonarqube_quality_profile.backend.key

  lifecycle {
    replace_triggered_by = [sonarqube_quality_profile.backend.key]
  }
}
```

## Schema

### Required

- `language` (String) Key of the language of the profile, such as `java`, `py` or `js`. SonarQube Cloud refuses a key that is not valid, and its error gives the valid keys.
- `name` (String) Name of the profile. The names of the profiles of a language must be different. Names are case-sensitive.
- `organization` (String) Key of the organization that owns the profile.

### Optional

- `parent_key` (String) Key of the profile that this profile extends. The parent must have the same language. When not set, the profile extends no other profile.

### Read-Only

- `id` (String) Key of the profile.
- `key` (String) Key of the profile. Use it as the `parent_key` of a different profile.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# The ID is <organization>/<language>/<name>. The name can contain "/".
terraform import sonarqube_quality_profile.backend "my-organization/java/Backend"
```
